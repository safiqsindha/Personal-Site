One HTML file, no build step

Why this site is a single 90 KB file with zero image requests — and the constraints that kept it that way.

Oct 6, 2026 · 3 min read

The homepage of this site is one file. Markup, styles, and scripts all live in index.html. There's no framework, no bundler, and no build command — deploying is copying files to Cloudflare Pages.

That wasn't an accident. It was the first constraint I set, and most of the interesting decisions came from refusing to break it.

Zero image requests

Every illustration on the page — the postcard scenes, the ridgelines, the paper grain — is hand-written inline SVG. The grain is a single feTurbulence filter in a data URI. The page renders without fetching a single additional image, which keeps the whole thing around 90 KB.

Motion that behaves

Things move, but politely:

  • Ridgeline parallax and the badge pendulum share one requestAnimationFrame loop that stops scheduling itself once nothing is moving.
  • Geometry is measured on load and resize only — never per frame — so scrolling never forces a layout.
  • Postcard animations pause when they're off-screen, via IntersectionObserver.
  • prefers-reduced-motion turns all of it off.

It degrades to a resume

Hit print and the page collapses into a plain document: the illustrations disappear, and the backs of the postcards become the body copy. Nothing important lives only behind an interaction — card fronts carry the headline facts, and the detail is one flip away.

What I'd tell someone building their own

Pick the constraint first and let it make decisions for you. "No build step" ruled out a lot of tempting libraries before I had to argue with myself about them. The full prompt I used is in the repository's BUILD-YOUR-OWN.md if you want a starting point.

And yes, there's a hidden game.
